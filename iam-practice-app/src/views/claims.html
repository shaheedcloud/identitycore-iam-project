Claims inspection

Claims are identity facts about the signed-in user, such as email, name, roles, groups, and department. Applications use those facts to decide what the user can access.

Roles and groups often appear in identity data because they are compact ways to describe authorization. In this app, route access is still local, but the examples show how future identity provider claims could influence the same decisions.

This page prepares for later OIDC and JWT work by showing token-like claim payloads before any real token validation exists.

This is not a real JWT. The simulated token uses alg: none, is not signed, and is only a local learning object.
