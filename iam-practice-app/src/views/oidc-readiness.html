OIDC readiness

OIDC is not active yet. The current app still uses local dummy login, sessions, local claims, and local RBAC.

In a later phase, real OIDC login will redirect to Entra ID or Okta. The identity provider will authenticate the user and redirect back to /auth/oidc/callback with an authorization code.

The server will later exchange that code for tokens. Tokens, client secrets, tenant values, and provider metadata must never be committed to GitHub.

ID token claims will later map to the app's local role and group model. Phase 4 will later handle JWT validation for protected APIs.

Phase 3A provides placeholders only. It does not start real OIDC login, exchange codes, store tokens, or validate JWTs.
